# Governance and Usage Boundary

## Purpose

Preserve the broader Operators Arsenal service inventory as a commercial reference for offer design, channel packaging, and capability expansion.

## Repository alignment

This document is **not** part of the canonical Operator Intelligence assessment methodology, scoring system, finding registry, recommendation router, implementation package catalog, or release gate. Operator Intelligence remains a governed Business Growth Systems Assessment for contractor and local-service businesses.

## Inputs and triggers

Use this catalog when:

- designing a bounded marketplace or direct-sales offer
- selecting adjacent fulfillment modules
- planning an expansion path after an evidence-backed assessment
- mapping capabilities to a specific buyer problem
- creating a channel-specific service listing

## Outputs

Permitted outputs include:

- fixed-scope audit offers
- implementation sprints
- clearly bounded builds
- retainer concepts
- marketplace gig structures
- discovery questions and qualification criteria

## Governance rules

1. Do not route a catalog item into an Operator Intelligence report unless evidence, score weakness, impact, confidence, priority, package eligibility, and roadmap phase justify it.
2. Do not treat catalog availability as recommendation evidence.
3. Do not make unsupported ROI, revenue, ranking, savings, compliance, security, or performance claims.
4. Separate assessment, proposal acceptance, implementation authorization, and realized-value validation.
5. Mark missing client evidence as `unknown`, `validation_required`, or `blocked`.
6. Use ALLOW / REVIEW / HALT gates for material scope, authority, privacy, security, legal, financial, or autonomous-execution decisions.
7. Preserve DecisionLedger traceability for any Operator Intelligence engagement output.
8. Channel listings may simplify language, but they must not weaken evidence, scope, authorization, or claim boundaries.

## Usage instructions

Lead with a small number of flagship offers. Treat the remaining services as fulfillment modules, add-ons, or later-stage expansion paths. Each published offer should define buyer fit, inputs, deliverables, exclusions, timeline, revision policy, acceptance criteria, and escalation conditions.

## Commercial v1.0 connection

This reference expands commercial packaging options after the Operator Intelligence v1.0 methodology and release controls. It does not modify the v1.0 scoring, finding, recommendation, package, lifecycle, or publication architecture.

This library supports a real services business, not merely a prompt store. The inventory breaks into three sellable lanes: **AI systems**, **business growth**, and **work efficiency / operations**. Each can be sold as a fixed-scope audit, build sprint, implementation, or monthly retainer.

# 1. AI Systems, Agents, Governance & Technical Services

## AI strategy, architecture, and deployment

- **AI Readiness & Opportunity Audit** — identify high-value AI use cases, data gaps, constraints, and a 90-day implementation sequence.
- **AI Operating Model Design** — define where AI belongs, ownership, automation boundaries, and human responsibilities.
- **Multi-Model Routing Design** — assign models by quality floor, cost ceiling, latency, and fallback rules.
- **AI Cost & Token Economics Audit** — model AI spend per workflow, routing arbitrage, and cost sensitivity.
- **AI Vendor / Platform Due Diligence** — assess vendor architecture, risk, fit, controls, and operating cost.
- **Self-Hosted vs API AI Feasibility Study** — calculate break-even including hardware, reliability, latency, and operating burden.
- **AI Capability Gap Roadmap** — decide what to build, buy, partner for, or skip.
- **AI Workflow Prioritization Sprint** — score workflows by volume, repetition, error cost, data readiness, and automation upside.
- **AI Output Reliability Program** — create output schemas, quality standards, fallback paths, and review logic.
- **Prompt / Skill Library Audit & Standardization** — consolidate, score, repair, deduplicate, and govern prompts or skills.

## AI agent systems

- **AI Agent Discovery & Design Sprint** — define purpose, tools, permissions, decision rights, failure paths, and success measures.
- **Production AI Agent Build** — build an agent with tools, APIs, execution logic, structured outputs, and safety controls.
- **Multi-Agent System Architecture** — design agents, state objects, contracts, orchestration, handoffs, and containment.
- **Sales Ops Agent System** — automate qualification, enrichment, follow-up, CRM updates, and proposals.
- **Client Delivery Agent System** — scale a productized service beyond founder hours without losing quality.
- **Agent Runbook Design** — create triggers, procedures, stop conditions, escalation paths, and audit trails.
- **Human SOP-to-Agent Conversion** — translate existing processes into agent-run workflows with checkpoints.
- **Unattended Agent Build Architecture** — structure long-running agent work with self-verification and safe stopping points.
- **Agent Evaluation Harness** — build test cases, scoring rubrics, regression checks, drift alarms, and release gates.
- **Agent Failure-Path Audit** — find cascading failures, hidden dependencies, and weak escalation points.
- **Agent Reliability & Regression Program** — establish recurring tests and benchmarks for prompts, agents, and workflows.

## AI governance, risk, and security

- **AI Governance Audit** — assess AI workflows for risk, autonomy, data exposure, decision rights, and auditability.
- **ALLOW / REVIEW / HALT Governance Design** — create decision gates with rules, owners, escalations, and evidence trails.
- **Policy-to-Control Conversion** — turn plain-English policies into enforceable workflow gates and controls.
- **AI Decision-Rights Charter** — define human and AI authority, escalation, override rights, and evidence trails.
- **AI Risk Register Quantification** — convert qualitative risks into probability bands, impact ranges, and mitigation budgets.
- **EU AI Act / NIST Readiness Assessment** — map systems to obligations, evidence gaps, and remediation actions.
- **AI Compliance Evidence Program** — collect and maintain audit-ready proof for relevant controls.
- **AI Governance Red-Team** — test governance bypasses, patch weak controls, and retest.
- **Policy Logic Audit** — detect contradictory, unreachable, incomplete, or unenforceable rules.
- **Incident-to-Policy Hardening** — convert postmortems into controls, gates, monitoring, and recurrence prevention.
- **AI Regulatory Monitoring Retainer** — track regulatory changes and map them to current controls.
- **AI Security Architecture & Threat Model** — map trust boundaries, threats, attack paths, controls, and priorities.
- **AI / Product Attack-Surface Assessment** — identify entry points, abuse paths, kill chains, and defensive gaps.
- **Security Advisory Impact Assessment** — determine actual CVE exposure and define the patch path.
- **Security Controls & Incident Readiness Validation** — test detection, response, evidence, and recovery readiness.
